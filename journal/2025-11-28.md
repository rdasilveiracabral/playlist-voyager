# Development Journal - 2025-11-28

## Initial Implementation Complete

### What was built today

**Backend (Python/FastAPI):**
- `main.py` - FastAPI app with CORS configuration for local frontend
- `auth.py` - Spotify OAuth flow using Spotipy library
- `config.py` - Environment variable management
- `store.py` - In-memory data store with JSON file persistence
  - Chose JSON over SQLite for simplicity (7000 songs fits easily in memory)
  - Data persists across server restarts via `data/spotify_cache.json`
- `spotify_client.py` - Spotify API wrapper with rate limiting
  - Batch fetching: 50 tracks/request, 100 audio features/request, 50 artists/request
  - ~240 API calls to sync 7000 songs
- `tracks.py` - Track endpoints (search, temporal neighbors, sync)
- `genres.py` - Genre hierarchy and graph data for visualization
  - 15 super-genres (rock, electronic, hip-hop, etc.)
  - Maps Spotify's ~1700 fine-grained genres to super-genres
- `llm_prompts.py` - Configurable prompts for Claude genre classification
  - Used when artists have no Spotify genre data
  - Results cached in JSON store

**Frontend (React/TypeScript/Vite):**
- `App.tsx` - Main app with auth flow, navigation tabs, sync UI
- `TemporalSearch.tsx` - Search songs, show 5 before/after by save date
- `StyleGraph.tsx` - Cytoscape.js force-directed graph
  - Super-genre nodes (large) connected to fine genre nodes (small)
  - Zoom reveals labels, click shows sample tracks with album art
- `SessionPath.tsx` - Recent plays timeline grouped by date
- `AudioFeatures.tsx` - 2D scatter plot with album art as points
  - Configurable X/Y axes (energy, danceability, valence, etc.)
- `TrackCard.tsx` - Reusable track display component
- `lib/api.ts` - TypeScript API client with full type definitions

**Styling:**
- Dark theme inspired by Spotify
- Green accent (#1DB954)
- Gradient backgrounds, glow effects
- Album art prominently featured throughout

### Design Decisions

1. **In-memory + JSON vs SQLite**
   - User asked if SQLite was necessary for 7000 songs
   - Decided JSON file cache is simpler and sufficient
   - Faster startup (load JSON vs 240 API calls)
   - Easier to inspect/debug

2. **React + Cytoscape.js vs alternatives**
   - Considered vanilla JS, Svelte, Vue
   - Chose React for best Cytoscape.js integration and ecosystem
   - User confirmed preference for web app over Python-only

3. **Genre classification hierarchy**
   - Spotify provides ~1700 genres at artist level only (not track level)
   - Created 15 super-genre categories for coarse view
   - MusicGenreDB (Every Noise archive) has 6,291 genres - can integrate later
   - LLM fallback for artists with no Spotify genre data

4. **LLM prompt configurability**
   - Moved prompts to separate file (`llm_prompts.py`)
   - User can customize classification behavior
   - Results cached to avoid repeated API calls

## Session 3: Style Graph Connectivity

### User Prompt
> "do all the above suggestions to make the graph more connected"

Graph was showing disjoint clusters because edges only connected fine genres to their parent super-genre.

### Changes Made

#### Backend (`genres.py`)
Added two new edge types to `/genres/graph-data`:

1. **Co-occurrence edges** (`type: "cooccurrence"`)
   - Connect fine genres that appear together on the same artist
   - Only included if weight >= 2 (at least 2 artists share both genres)
   - Result: 609 new edges

2. **Bridge edges** (`type: "bridge"`)
   - Connect super-genres when artists span multiple categories
   - Only included if weight >= 3 (at least 3 artists bridge those super-genres)
   - Result: 40 new edges

#### Frontend (`StyleGraph.tsx`, `api.ts`)
- Different styling for each edge type:
  - Parent edges: gray, subtle (opacity 0.2)
  - Co-occurrence: green (#1DB954), width varies by weight
  - Bridge: purple (#9333ea), thicker, more prominent
- Updated TypeScript types for new edge properties
- Stats display shows connection count

### Result
Graph now shows how user's music taste bridges different styles, with connected clusters based on shared artists.

## Session 4: Super-Genre Track Lists Fix

### User Prompt
> "why don't the big clusters show a track list on click?"

### Problem
Super-genre (big cluster) nodes were not showing track lists when clicked, while fine-genre nodes worked correctly.

### Root Cause
Super-genre nodes in both `/genres/graph-data` and `/genres/graph-data/temporal` endpoints were missing the `sample_tracks` property. The fine-genre nodes had sample tracks collected, but super-genres didn't aggregate them.

### Fix (`genres.py`)
Modified both endpoints to collect sample tracks for super-genres:

```python
super_genre_counts = {}
super_genre_samples: dict[str, list] = {}
for genre, data in genre_data.items():
    sg = data["super_genre"]
    super_genre_counts[sg] = super_genre_counts.get(sg, 0) + data["count"]
    # Collect sample tracks for super-genre
    if sg not in super_genre_samples:
        super_genre_samples[sg] = []
    if len(super_genre_samples[sg]) < 10:
        for track in data["sample_tracks"]:
            if len(super_genre_samples[sg]) < 10:
                super_genre_samples[sg].append(track)

# Then include in node data:
"sample_tracks": super_genre_samples.get(super_genre, []),
```

Now both Artist Affinity and Temporal Affinity views show track lists for super-genre nodes.
